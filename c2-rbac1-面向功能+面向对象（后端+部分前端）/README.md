## 当前已实现

- 角色直接/多级继承、多路径去重；自继承、成环、跨归属和越权拒绝。
- 原会话实时判权；删除唯一有效路径提交后拒绝，仍有合法替代路径则继续允许。
- 组织停用、重开与同源重授；员工、角色、权限和分配关系维护。
- 申请发起、列表/详情、修改、撤回、审批、驳回和本人逻辑删除；查看权与动作权分别验证。
- `/func/`、`/oo/` 共用前端，独立数据库、Cookie 和 Redis 会话命名空间。
- 课程三份 Excel 导入与分页全量核对；申请 Logback 审计和事务结果记录。

正式源码为 `backend-func/`、`backend-oo/`、`frontend/`；`测试/` 集中维护测试与证据。三模型中的满血内存小样用于设计对照，无需部署成第三套后端。正式图件 42 张，比较小样另外新增 2 张，四张复用图不重复计数。

## 本机测试与启动

1. 准备 Java 21、Maven、满足 frontend engines 的 Node，以及 MySQL/Redis。两版分别创建开发库和独立 `_test` 测试库。
2. 从 C2 根目录执行 `mvn -f backend-func/tools/clonefactory/pom.xml install`，相同制品供两版编译。
3. 为每版设置自己的 `RBAC_DB_URL`、`RBAC_DB_USER`、`RBAC_DB_PASSWORD`，以及 `RBAC_REDIS_HOST`、`RBAC_REDIS_PORT` 等；两版会话参数保持隔离。详细变量见部署交接文档。
4. 两版分别构建 JAR；演示初始化使用 `--init-demo` 和 `RBAC_DEMO_ACCOUNTS_ENABLED=true`。原表导入使用 `--import-excel=<目录>`，两个命令分开执行，结束后退出。
5. 正常启动 JAR，不带初始化选项；本地后端端口为 18181/18182。在 frontend 执行 `npm ci`、`npm run dev`，访问 `http://127.0.0.1:5173/`。

账号、操作和本地代理见 [前端运行说明](./frontend/README.md)，原表私下提供。生产环境需单独实现网关转发，Vite 代理不会随 dist 自动部署。

真实后端回归从 C2 目录执行：

```powershell
python ./测试/脚本/run_backend.py func
python ./测试/脚本/run_backend.py oo
```

本机运行器读取约定的本地依赖，只连接专用 `_test` 库；异地环境按 [测试说明](./测试/README.md) 配置，不能原样指向演示库。测试源码随仓库交付，不需要作为常驻服务或放入生产 JAR。
