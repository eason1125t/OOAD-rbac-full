# C2 项目总结

更新日期：2026-11-22。范围为 RBAC1 的本地实现与交付材料。代码、设计、测试、三模型比较和 GRASP 已完成；本文与答辩材料已形成，Swarm 部署及部署后的实测结果待队友补齐。

## 1. 一句话认识 C2

**用同一套业务要求和前端，对照“按功能步骤组织”和“按对象职责组织”的两套 RBAC1 后端，展示角色继承如何影响真实业务操作。**

用户在 `/func/` 与 `/oo/` 切换版本；前端共用，后端与数据库按版本独立。满血模型是额外的教学小样，不属于第三套线上后端。

## 2. 已完成什么

| 内容 | 用户能看到的效果 | 核心实现 |
| --- | --- | --- |
| 基础权限管理 | 管理员工、角色、权限，以及员工角色和角色权限关系 | 延续 C1 的 RBAC0 关系和管理范围校验 |
| 角色继承 | 主管通过继承获得审批员权限；支持多级、多路径 | 有向无环图，直接边存库，权限按闭包展开并去重 |
| 继承保护 | 自继承、循环继承、跨归属与越权维护被拒绝 | 应用规则、同一图写锁、事务和数据库约束协作 |
| 实时撤权 | 删掉唯一有效路径后，原登录下一次操作被拒绝 | JWT仅承载身份，Redis在线核对sid，本次授权读取当前关系；替代路径仍有效时继续允许 |
| 组织策略 | 公司/部门范围内停用、重开和显式重授 | 停用优先；同一权限来源满足所有适用的重开组织要求 |
| 业务申请 | 发起、查看、修改、撤回、审批、驳回、逻辑删除 | 查看权与动作权分开；状态和本人边界由后端复核 |
| 双版隔离 | 同一浏览器可分别登录、操作和退出两版 | 独立 MySQL 库，独立密钥/issuer/audience、刷新Cookie及Redis登录命名空间 |
| Excel 全量浏览 | 查看课程员工、组织和功能权限清单 | POI 导入、来源标记、分页、组织匹配与电话脱敏 |
| 日志与验证 | 操作结果有日志，设计有代码和测试证据 | Logback、JUnit、真实 MySQL/Redis 集成、Playwright、JaCoCo |

申请允许有相应权限者审核本人申请；撤回为终态；只有本人可以删除已驳回申请。这些是当前需求，不自行增加 RBAC2 的职责分离约束。

## 3. 两套后端及三模型比较

| 对比项 | func：偏贫血、过程式 | oo：富行为、局部领域设计 | 满血：隔离内存小样 |
| --- | --- | --- | --- |
| 业务组织 | Service 顺序编排步骤 | Service 协调，领域对象维护自己的规则 | 领域对象还协调选定用例的装载与保存 |
| 角色图 | Graph 保存数据，静态 Rules 计算 | RoleHierarchy 持有不可变快照并计算 | FullRoleHierarchy 经两个窄端口协作 |
| 申请状态 | Service.applyChange 检查并设置字段 | BusinessRequest.rename/approve 等方法维护状态 | 小样不包含申请模块 |
| 存储 | Service 直接使用具体存储较多 | 申请模块经业务端口访问适配器 | 内存存储，无真实数据库事务与并发保证 |
| 优点 | 流程直观、便于按步骤跟读 | 数据与行为集中，部分规则可独立验证 | 便于观察职责进一步迁移的代价 |
| 代价 | 用例复杂后 Service 容易变长 | 类型与映射增多，边界需要维护 | 领域对象知道更多协作时机，测试准备增加 |

**结论：比较职责与取舍，不把三种名称当作优劣排名。** 正式项目保留 func/oo 两条线。对象版没有将所有 C1 模块全面改成 DDD；RoleHierarchy 负责计算，不修改和保存继承边。

“满血”采用本项目已确认的工作定义，不是行业统一等级。完整设计、六个对照视图和小样见 [三模型比较](../../三模型比较/README.md)。

## 4. GRASP 在哪里，如何对照

| 原则/关注点 | 功能版 | 对象版的具体体现 |
| --- | --- | --- |
| 信息专家 | 静态规则接收显式数据；Service 检查申请状态 | RoleHierarchy 掌握图；BusinessRequest 掌握状态与申请人 |
| 用例控制器 | Service 编排流程 | Service 同样组织事务和外部协作，HTTP Controller 负责适配 |
| 创建者 | 在用例步骤中准备数据并构造对象 | 存储实现掌握边数据并创建快照；Service 掌握可信输入并发起申请创建 |
| 高内聚 | 按功能集中相关步骤 | 图规则、申请状态、持久化与审计分别集中 |
| 低耦合、间接性 | 用例直接依赖仓储和统一授权较多 | 申请 Service 依赖 RequestRepository、RequestSystems、RequestAccess |
| 多态机制 | 框架仓储也使用接口机制 | 业务端口由具体适配器实现；当前并没有多套运行算法可选 |
| 纯虚构、受保护变化 | 同样存在专门技术协作对象 | 存储/上下文适配器与审计对象隔开技术细节；共同契约约束外部行为 |

功能版也能做到职责清楚、较高内聚；接口多不等于设计更好。CloneFactory 是映射工具，不等于 GRASP Creator。逐项解释、源码与测试、追问依据见 [grasp与项目.md](grasp与项目.md)。

## 5. 技术选择：为什么用、用在哪里

| 技术 | 选择理由与项目用法 |
| --- | --- |
| Java 21、Spring Boot | 两版共用基础运行平台，提供依赖注入、Web 和事务支持 |
| Spring MVC、Bean Validation | Controller 接收 HTTP；DTO 校验请求格式，业务规则由 Service/领域对象承担 |
| Spring Security | 会话身份、请求安全与 CSRF；业务权限仍由统一授权逻辑判断 |
| Spring Security JWT、Redis | RS256验签、独立sid在线撤销与严格刷新；不保存业务权限快照，已退出Spring Session |
| MySQL、JPA | 保存员工、角色、关系、策略和申请；使用关系约束和行锁保护一致性 |
| Flyway | V1—V9 管理数据库版本（含API映射两表）；Hibernate validate 检查映射，不自动任意改表 |
| Lombok | 减少访问器与注入构造器的重复代码 |
| CloneFactory | 注解处理器在编译期生成同名同类型字段映射，减少服务结果和 VO 赋值样板 |
| Apache POI | 解析课程 Excel，处理原表结构与来源关联 |
| Vue、TypeScript、Vite | 共用界面、类型检查和本地开发；生产网关需要另配两版 API 转发 |
| Logback、AOP | 方法耗时与异常类型日志；申请审计记录版本、对象 ID、动作和最终结果 |
| JUnit、JaCoCo、Playwright | 分别验证规则/集成行为、统计覆盖率、验证真实页面流程 |
| OpenAPI、Apifox | 前者维护共同契约，后者用于文档协作和接口调试 |
| Docker、Swarm | Docker 已用于本机依赖；Swarm 是课程服务器交付目标，待实际部署验证 |

## 6. 三条技术实现主线

**新增继承：** 可信操作者 → 管理资格 → 全局图写锁 → 双端范围 → 同归属/自继承/幂等 → 从 junior 查到 senior 的可达性 → 增量授权影响 → 保存并提交。先锁后读和 READ_COMMITTED 事务防止并发新增共同成环；不可变 Map 本身不能保证跨进程安全。

**申请审批：** Controller → Service 锁定申请 → 解析数据库中的所属系统 → 当前查看权＋审批权 → 状态检查/转换 → 保存 → 事务完成后记录结果。func 在 Service 中处理状态；oo 由申请对象执行状态行为。

**实时撤权：** 管理员提交删边 → 员工沿用原会话发下一次请求 → 根据当前 MySQL 角色关系和组织策略重新判权。没有有效来源就拒绝，有合法替代路径则继续允许。

## 9. 本地运行与演示

详细参数见 [前端运行说明](前端说明-整理前.md)、[测试说明](../../测试/归档/测试说明-整理前.md)。概要步骤如下：

1. 准备 Java 21、Maven、满足 frontend engines 的 Node，以及 MySQL/Redis；为两版建独立开发库。
2. 在 C2 目录执行 `mvn -f backend-func/tools/clonefactory/pom.xml install`，相同制品供两版使用；配置各版数据库凭据、Redis 地址和版本会话参数。
3. 分别构建两版，按需执行一次 `--init-demo`；演示账号需显式启用 `RBAC_DEMO_ACCOUNTS_ENABLED=true`。三份课程原表分别用 `--import-excel=<目录>` 导入，两个命令分开执行并自动退出。
4. 分别启动后端 JAR，本地端口为 18181/18182；前端执行 `npm ci`、`npm run dev`，进入 `http://127.0.0.1:5173/`。
5. 从两个版本入口分别演示登录、继承、权限查询、申请操作及日志；生产服务器按部署交接配置网关，不沿用本机地址。
