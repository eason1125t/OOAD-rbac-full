## 当前已实现

- 角色直接/多级继承、多路径去重；自继承、成环、跨归属和越权拒绝。
- 同次登录实时判权；删除唯一有效路径提交后拒绝，仍有合法替代路径则继续允许。
- 组织停用、重开与同源重授；员工、角色、权限和分配关系维护。
- 申请发起、列表/详情、修改、撤回、审批、驳回和本人逻辑删除；查看权与动作权分别验证。
- `/func/`、`/oo/` 共用前端，独立数据库、密钥/issuer/audience、Cookie和Redis登录命名空间。
- 课程三份 Excel 导入与分页全量核对；申请 Logback 审计和事务结果记录。
- 本轮后端新增可信身份入口、指定系统自身角色/有效权限及单项判断、正式部门树和范围内员工搜索分页、指定API权限预查询；前端已接入身份权限面板、申请按钮、共用部门员工查询和管理员资料。

正式源码为 `backend-func/`、`backend-oo/`、`frontend/`；`测试/` 集中维护测试与证据。三模型中的满血内存小样用于设计对照，无需部署成第三套后端。正式图件49张，比较小样另外新增 2 张，四张复用图不重复计数。

## 本机测试与启动

当前源码前后端及部署模板已切JWT；必须使用同一批新构建，旧Session不能延续，用户需重新登录。后端需准备外部密钥；当前本机服务已成套切换，启动/停止使用部署/local.ps1。完整运行与证据见[JWT整体验收](../../测试/归档/JWT前端与整体验收.md)。

1. 准备 Java 21、Maven、满足 frontend engines 的 Node，以及 MySQL/Redis；后端测试运行器另需OpenSSL生成临时测试密钥。两版分别创建开发库和独立 `_test` 测试库。
2. 从 C2 根目录执行 `mvn -f backend-func/tools/clonefactory/pom.xml install`，相同制品供两版编译。
3. 为每版设置自己的 `RBAC_DB_URL`、`RBAC_DB_USER`、`RBAC_DB_PASSWORD`，以及 `RBAC_REDIS_HOST`、`RBAC_REDIS_PORT` 等；另设置RBAC_JWT_PRIVATE_KEY_LOCATION、RBAC_JWT_PUBLIC_KEY_LOCATION指向外部PEM资源；两版认证参数保持隔离。当前JWT调试见[第3部分运行说明](../../测试/归档/JWT登录生命周期验证.md)，部署模板已挂载两版独立密钥并使用新认证参数，见[部署说明](../../部署/归档/部署说明-整理前.md)。
4. 两版分别构建 JAR；演示初始化使用 `--init-demo` 和 `RBAC_DEMO_ACCOUNTS_ENABLED=true`。原表导入使用 `--import-excel=<目录>`，两个命令分开执行，结束后退出。
5. 正常启动 JAR，不带初始化选项；本地后端端口为 18181/18182。在 frontend 执行 `npm ci`、`npm run dev`，访问 `http://127.0.0.1:5173/`。

账号、操作和本地代理见 [前端运行说明](前端说明-整理前.md)，原表私下提供。生产环境需单独实现网关转发，Vite 代理不会随 dist 自动部署。

真实后端回归从 C2 目录执行：

```powershell
python ./测试/脚本/run_backend.py func
python ./测试/脚本/run_backend.py oo
```

本机运行器读取约定的本地依赖，只连接专用 `_test` 库；异地环境按 [测试说明](../../测试/归档/测试说明-整理前.md) 配置，不能原样指向演示库。测试源码随仓库交付，不需要作为常驻服务或放入生产 JAR。
