# C2 前端运行与验收

## JWT认证协作

页面仍使用现有登录表单。`auth.ts`与`auth.worker.ts`以同源SharedWorker集中保存内存访问JWT，按func/oo分别命名；同版标签页的登录、刷新、退出串行执行。多个过期请求复用同一次刷新结果，避免严格轮换下误把另一标签页当成重用攻击。页面刷新或工作区整页导航后，先取得访问凭证，再读取me；所有页面关闭后内存消失，下次打开用HttpOnly刷新Cookie恢复。

`api.ts`为业务统一发送Bearer，只有明确的401 `ACCESS_TOKEN_EXPIRED`允许刷新并重试原操作一次。403、503、断网和执行结果未知的写入均不自动重放。请求记录随机sid归属，账号变化后丢弃旧响应，不以新账号重发旧写入；这不是tokenVersion。账号切换/退出事件先卸载旧权限与目录页面。

只有登录、刷新和退出由协调器先取CSRF并使用Cookie；业务写入不领取CSRF。JWT、刷新凭证不存localStorage/sessionStorage、不写URL或日志。支持现代桌面Edge/Chrome等SharedWorker浏览器；不支持时给出明确提示并拒绝不协调的刷新。HTTP开发使用可用的crypto.getRandomValues，生产HTTPS须启用Secure认证Cookie。前端更新导致旧标签页协调器冲突时，关闭本版旧标签页重新打开。

刷新遇网络结果不确定或503时，协调器停止透明刷新，保留Cookie并提示故障；恢复服务后显式退出/重新登录。不会重发可能已消费的刷新凭证。真实浏览器测试的过期响应桩仅用于触发客户端分支，签名、实际到期、重用与8小时上限由后端测试验证。

JWT迁移状态（2026-11-22）：第4部分已接入Bearer、内存凭证、页面恢复和同版多标签页协调，第5部分整体验收见[当前验证记录](../../测试/归档/JWT前端与整体验收.md)。当前本机18181/18182与5173已成套切换JWT，原Session用户需重新登录；见[切换记录](../../测试/归档/JWT本机切换记录.md)。

`/func/` 连接面向功能后端，`/oo/` 连接面向对象后端。两个入口使用同一个 Vue 构建，由同源代理按路径选择后端及独立登录。

1. 在两套后端的独立演示库各运行一次 `--init-demo`。启用 `RBAC_DEMO_ACCOUNTS_ENABLED=true` 后，命令会创建或更新以下八个演示账号，密码统一为 `1234`。
2. 对需要全量验收的库分别运行 `--import-excel=<原表目录>`。两种初始化命令执行后退出。
3. 启动功能版后端使用 `SERVER_PORT=18181`，对象版使用 `SERVER_PORT=18182`，再在本目录运行 `npm ci` 和 `npm run dev`。若使用其他端口，可配置 `RBAC_FUNC_API_TARGET` 和 `RBAC_OO_API_TARGET`。打开 [本机首页](http://127.0.0.1:5173/) 选择版本。

| `super-admin` | 全局管理 |
| `company-a-admin` | 公司管理与公司申请 |
| `engineering-employee` | 工程部申请 |

对已经初始化的演示库运行同一命令可补齐新增账号。演示初始化保留用户对继承关系和组织策略的修改。如果工程审批已重新开放，需由管理员对「示例继承审批来源」重授后再用继承账号审批。

读取申请需要该系统的 `request:read`。八个演示账号按所属工作区配置了查看角色，全局管理员按既有规则授权。其他账号升级后由管理员显式授予查看权。撤销查看权后，原页面下一次读取会清空旧列表和详情。处理已有申请还需要相应动作权限。第6步修正前端按钮不再依赖列表成功：只有create没有read仍可发起，列表和详情保持清空。

用 `super-admin` 登录后，打开「角色管理 → 测试工程主管 → 管理权限」。这个角色从「示例继承审批来源」继承「工程申请审批」，权限页会标出继承权限的只读状态。直接授权时先选择业务系统，再选择动作。角色配置与员工在组织策略下的实际权限可分别在「管理权限」和「员工管理 → 有效权限」核对。

## 生产入口与交接

只发布这一份前端构建，分别通过 /func/、/oo/ 访问两个 Swarm 后端。Vite 的本地 server/preview 代理不会随 dist 生效；生产网关须实现 API 前缀去除、Cookie/CSRF 透传与页面深链回退，API 优先于 SPA 回退。前端、两后端和数据库均进入 Swarm；具体参数、Apifox 环境与双版服务器 Logback 验收见 [部署交接文档](../../部署/归档/部署交接文档.md)。

现有 Playwright 默认运行本地 Vite；11月19日本机23项报告属于历史批次；第6步新增33项隔离浏览器验证（不含真实Excel全量），均不等于集群验收结果。部署后从浏览器/Apifox 请求真实入口验证，新增远程配置通过 RBAC_DEPLOY_BASE_URL 直接访问站点，复用 3 项入口/隔离测试；见 [部署验证](../../测试/归档/部署验证记录.md)。项目整体讲解见 [项目总结](项目总结-整理前.md)，老师追问见 `答辩文档.md`（本地待完善，暂不上传）。

## 第6步接入后的使用

业务工作区展开“我的角色与权限”，可查看指定系统的直接/继承角色与来源、相关性、有效权限，并检查单个前端权限码或八种申请操作的API权限。列表及按钮复用当前系统的有效权限；点击申请列表“刷新”也重新读取授权。切换系统会重新读取该系统数据，错误不会沿用旧授权。

顶部“部门与员工”供管理和业务工作区共用。先逐层展开公司，选择部门后按姓名/账号查询员工；也可搜索可见部门或查看全部可见员工，部门与员工独立分页。普通员工只见最小字段；管理员可点击“查看资料”查询范围内资料，电话沿用后端遮盖。原管理页及Excel原表目录保留。

前端控制只改善操作体验，实际API继续检查身份、系统准入、实时权限、申请归属与状态。API预查询通过不等于具体申请能操作，未知目标或服务错误也不等于allowed=false。

配套后端必须为本轮新包（例如两版target/jwt-final），完成V1～V9及所需演示初始化。当前18181/18182已切到JWT新包；将来仅构建前端仍不会自动升级后端；可按运行说明换新包，或用RBAC_FUNC_API_TARGET/RBAC_OO_API_TARGET指向新后端，保持同源代理和两版Cookie隔离。

从C2根目录执行独立浏览器验收：

```powershell
python 测试/脚本/run_frontend_identity.py --output-dir 测试/结果/前端接入-新批次 --suite regression
```

运行器使用独立UI测试库、临时28181/28182及15173，构建后以Vite预览验收；结束停止自己启动的后端。请选新的空目录保留历史报告。[33项实际结果、截图、范围与限制](../../测试/归档/前端身份接入验证.md)。

Session阶段第7步的35项浏览器保留为[历史验收](../../测试/归档/最终验收.md)。JWT完整验收应使用--suite full --excel-dir ../excel --backend-build-dir target/jwt-final，并提供新的空归档目录；每批新建独立final_test库，密钥在工作区外临时生成，见[JWT验收](../../测试/归档/JWT前端与整体验收.md)。
