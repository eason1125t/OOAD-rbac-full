## 重点纠正的说明

- 继承写入先取管理员资格，再取全局图写锁，随后校验双端详细范围；继承服务本身不取角色行锁。授角、授权限、停用和重授各有实际锁顺序，文档分别列明。
- 直接权限、继承配置权限和员工实际有效权限含义不同。有效权限先完整计算再内存分页，其余主要目录在数据库分页。
- 组织停用早于全局特权；同一个直接权限来源必须满足全部适用重开范围，不能拼接不同来源的重授。
- Redis 只保存可信身份会话，不缓存权限。撤权后下一次请求重判，不宣称取消已通过鉴权的在途事务。
- 申请方法返回不等于提交成功。BusinessRequestAudit 是集中事务结果日志入口，afterCompletion 才确认 COMMITTED；AOP 方法日志不能替代它。
- 方法日志当前沿用 `rbac0.api/service/infrastructure`，申请结果日志按版本使用 `rbac1.func/oo.request`。AOP 未普遍覆盖所有 Repository/适配器，当前也没有自定义 Logback XML。
- 登录、初始化、组织和组织策略仍主要沿用 C1 Service/JPA；对象版明确的变化是角色图领域封装和申请的领域/端口/适配器，不虚称全系统完成 DDD。
- 演示初始化保留人工撤权、继承边和组织策略改动；非 Web 模式不等于 main 显式关闭上下文。工作簿使用 Apache POI，演示密码当前是合成账号常量。

## CloneFactory 使用与保留边界

两版各有六处 `@CopyFrom`：组织 VO、清单 VO、申请服务的摘要和详情、申请公开摘要和详情 VO。Lombok 与 CloneFactory 在 Maven 编译阶段协作生成字段映射，生成文件位于各版 `target/generated-sources/annotations/cn/edu/xmu/clonefactory/util/CloneFactory.java`。

本次保留既有映射注解、生成链和 `CloneFactory.copy`，编译确认生成正常。权限敏感字段、派生值、不可变 record 构造及对象版领域—持久化转换继续按明确边界处理，不以机械全字段复制绕过身份和状态规则。修改映射注解时应按项目规范重新生成并执行相应验证，本次没有修改这些注解。
