# C2 第二步：可信身份入口整理与验证

日期：2026-11-21（Asia/Shanghai）。本步只实现身份读取职责调整，不实现自身角色权限、部门树或 API 预查询，不迁移 JWT。

## 改动与调用关系

两版各新增 authentication/CurrentEmployeeService：

- findActive：可信员工 ID → 最新启用且有组织归属的 Employee；缺失/失效返回空，数据库故障继续传播。
- requireActive：用例所需的有效员工；缺失/失效抛出现有 AUTHENTICATION_REQUIRED，由统一 Advice 映射 401。
- canSignIn：登录和锁定目标员工授角共用的资格谓词，不证明任意员工已通过认证。

安全过滤器从已恢复的 Session principal 取得 ID，再用 findActive 复验；失效时结束旧会话。AuthController 和 AuthorizationService 使用 requireActive；WorkspaceService 专注组织、系统准入和工作区，不再依赖 EmployeeRepository。登录密码验证、会话建立/轮换/退出仍在 SessionAuthentication；角色继承、组织停用/同源重授、申请领域和事务逻辑保持原规则。

旧 AuthController 的私有身份读取和单独失效异常处理已删除，复用统一业务错误。授角仍对已加锁的目标员工做资格判断，不重新取无锁记录、不改变 ASSIGNMENT_CONFLICT。过滤器及业务用例可能各读一次身份，本步不引入身份缓存，也不承诺消除全部重复查询。

Controller/用例不能用请求中的 employeeId、username 代替当前身份。管理员已验证范围后的目标员工权限计算仍保留原用法；身份有效性与“有权操作某项业务”是两层检查。

## 命令、隔离构建和运行

本机实际启动现有 ooad-rbac-c2-dev-mysql、ooad-rbac-c2-dev-redis；测试严格使用 ooad_rbac1_func_test / ooad_rbac1_oo_test、33327/36390，不连接开发或演示业务库。凭据仅传子进程环境。

从 C2 根目录执行：

```powershell
python 测试/脚本/run_backend.py func --output-dir 测试/结果/可信身份-20261121/基线/func
python 测试/脚本/run_backend.py oo --output-dir 测试/结果/可信身份-20261121/基线/oo

python 测试/脚本/run_backend.py func --output-dir 测试/结果/可信身份-20261121/最终/func --build-dir target/identity-step2
python 测试/脚本/run_backend.py oo --output-dir 测试/结果/可信身份-20261121/最终/oo --build-dir target/identity-step2

node 测试/前端/report-images.mjs 测试/结果/可信身份-20261121/最终
```

本步为 runner 增加可选 --output-dir 和 --build-dir，默认用法不变。build-dir 限定后端 target 内的相对路径；POM 的 rbac.build.directory 默认 target，本批用 target/identity-step2，Surefire/JaCoCo 同目录。没有改依赖版本、测试源入口或生产认证配置，不执行 clean，不批量删除或移动目录。

本机已有两个 Java 开发进程监听 18181/18182，占用默认 JAR。首次修改后测试通过，但 repackage 重命名失败；进一步检查 .jar.original 不存在，尝试备份未移动任何文件，单独 repackage 也无法替代 package 生命周期。未结束既有进程，最终使用隔离输出目录完整构建。

首次失败归档器曾带出旧覆盖率，已明确作废；现已仅采集当前运行生成的 Surefire，构建失败时不归档覆盖率，无测试或有跳过都不作为完整验收通过。原始失败保留在结果/可信身份-20261121/完成后，只有最终目录作为本步有效结果。

本步新可运行 JAR 位于各版 target/identity-step2；既有 18181/18182 进程未部署新包。后续正常启动仍按 [C2 运行说明](../../docs/归档/入口说明-整理前.md)，如需运行本步隔离包，将原 java -jar 路径换成该目录的版本 JAR，并先安排释放对应端口；数据库、Cookie 和账号配置不变。不要把原 target 下首次打包失败留下的文件当成本步交付包。
