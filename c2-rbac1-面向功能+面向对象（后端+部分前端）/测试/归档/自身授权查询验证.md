# C2 第三步：自身角色权限与单项判断

日期：2026-11-21（Asia/Shanghai）。本步实现 ID-03 的指定系统自身授权响应和 ID-04 单项前端权限判断；其余部门/员工、API 映射与前端接入留待后续。

## 实现与使用

- GET /api/auth/me：保持旧三字段；登录响应也不增加 authorization。
- GET /api/auth/me?systemCode=demo-engineering-app：增加角色直接/继承来源、系统配置相关性、有效权限和全局管理员标志。
- GET /api/auth/me/permission-check?systemCode=demo-engineering-app&permissionCode=request:approve：当前用户的已知权限允许/拒绝；未知权限404、系统无准入403、输入错误400。

身份只来自 Session 的可信员工，不通过 employeeId/username 切换查询人。CurrentAuthorizationService 负责系统定位、调用统一授权和公开 record 映射；AuthorizationService 的 describe/hasBusinessPermission 与实际 requireBusinessPermission 复用同一 isAllowed。角色来源与配置相关性使用同一继承图快照，批量读取角色和目标系统权限来源，不添加角色—系统表或跨请求缓存。

direct 与 inherited 可以同时为 true；继承来源只列其他直接分配根，按 ID 去重排序。appliesToSystem 是配置相关性，不等于组织策略下有效；全局特权可以没有角色来源，仍被 DISABLED 拒绝。未知权限404仅新增查询入口使用，原实际操作缺动作仍403。管理员查询他人的权限和目标数据范围不变。

运行配置、账号和同源访问仍按 [C2 README](../../docs/归档/入口说明-整理前.md)。本步新 JAR 位于各版 target/identity-step3；现有18181/18182进程没有重启或部署新包，当前旧服务不代表本步新接口。需要手工体验时安排释放对应端口，再按原配置启动该目录的版本 JAR，经原 /func/ 或 /oo/ 代理访问上述路径。前端新界面在第6步接入；本步未实现JWT。
