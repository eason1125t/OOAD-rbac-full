# C2 第四步：部门与员工查询

日期：2026-11-21（Asia/Shanghai）。完成 ID-05 正式组织树及原目录筛选、ID-07 部门员工搜索分页；保留 ID-08 管理资料边界。API 映射、前端接入及JWT尚未实施。

## 实现及运行方式

- GET /api/departments：默认directory，保留原表公司行/部门和旧字段，仅管理员；允许q搜索。
- GET /api/departments?view=tree：可见范围根；parentId只查直接子级，rootsOnly=false范围内平铺，q按契约组合搜索。返回正式类型、真实parentId及仅限可见子级的hasChildren。
- GET /api/employees?departmentId=...&q=...&page=1&pageSize=20：范围AND部门AND（姓名OR账号），列表与count同条件，普通员工只看启用员工的四个最小字段；管理员投影及电话遮盖保留。
- GET /api/employees/{id}、他人角色/权限和所有管理写入保持管理员及目标范围检查；普通列表开放不连带开放详情或维护。

DirectoryVisibilityService集中普通员工及全局/公司/部门管理员读取范围；原ManagementQueryService复用该范围，保留公司、角色、权限、关联和管理详情用例。DirectoryQueryService使用JPA Specification在数据库执行筛选和count，按当前页批量判断子级；旧无调用固定目录方法移除，不保留第二套范围实现。维护写入的范围校验/锁顺序和业务系统授权规则未改。

普通员工只读自身组织，直接属于公司时也不自动扩展到部门；公司管理员含直属部门，部门管理员只有本部门。全局管理员未指定部门时仍可查看组织未匹配员工。hasChildren不泄露不可见分支，不受子级是否匹配q影响；可见根的parentId不改成伪null。公司节点只作树分组，departmentId要求DEPARTMENT。

q去首尾空白，%/_/!按字面匹配；mode组合和非部门ID错误400、未知组织404、越界403。沿用1基分页、默认20/最大100、稳定ID排序和no-store。未新增组织整体enabled、任意层级授权或组织写入。

本批在真实专用_test库执行；运行和账号配置仍见 [C2首页](../../docs/归档/入口说明-整理前.md)。新包在各版target/identity-step4，既有18181/18182开发进程未重启。需要手动体验时安排释放端口并按原配置启动该目录的JAR，经原版本代理访问接口；树和普通员工列表的前端界面待第6步接入。
