## 新包运行与迁移

最终可运行包：

- backend-func/target/identity-final/rbac1-func-0.1.0-SNAPSHOT.jar
- backend-oo/target/identity-final/rbac1-oo-0.1.0-SNAPSHOT.jar
- frontend/dist，由本批生产构建生成，两个入口共用。

保留各版原有RBAC_DB_URL、RBAC_DB_USER/RBAC_DB_PASSWORD、Redis及会话配置，按原启动方式将JAR路径换为本轮新包。启动会自动执行Flyway V9；不恢复旧迁移、不重置授权、继承和组织策略。需要四个演示系统映射时，按现有显式--init-demo流程补齐；已有损坏映射会拒绝并回滚，不自动掩盖。空库/V8升级及幂等行为已在最终后端回归执行。

在两版各自已配置好环境的终端，可从C2运行：

```powershell
java -jar ./backend-func/target/identity-final/rbac1-func-0.1.0-SNAPSHOT.jar --server.port=18181
java -jar ./backend-oo/target/identity-final/rbac1-oo-0.1.0-SNAPSHOT.jar --server.port=18182
```

以上两个进程需在不同终端运行。旧进程占用相同端口时应由其原管理方式切换，不要同时运行争用端口，也不要为了启动新包擅自换库。前端继续按原README在frontend运行npm run dev；API目标默认18181/18182，也可用原代理环境变量显式指向新后端。新前端不能搭配11月19日旧JAR。

Dockerfile仍从当前源码构建，包含V9及新前端；现有部署镜像不会因为修改源码自动升级。本轮未重建/推送镜像、未部署或回滚任何课程服务。
