## 从 C2 根目录运行

**无需数据库的快速检查：**

```powershell
mvn -f backend-func/pom.xml '-Dtest=RoleInheritanceRulesTest,WorkbookReaderTest,InitializationCommandTest' test
mvn -f backend-oo/pom.xml '-Dtest=RoleHierarchyTest,BusinessRequestTest,RequestArchitectureTest,WorkbookReaderTest,InitializationCommandTest' test
python 测试/图件/test_diagram_checks.py
```

**完整后端回归：** 启动本机 C2 MySQL/Redis 后运行。脚本使用约定容器和端口，凭据只放子进程环境；只连接专用 `_test` 库，不连接演示库。

```powershell
python 测试/脚本/run_backend.py func
python 测试/脚本/run_backend.py oo
```

分阶段结果可用 `--output-dir 测试/结果/批次/版本` 单独归档；已有开发 JAR 正在运行时，可加 `--build-dir target/identity-step2` 隔离构建输出（限定在后端 target 内）。默认目录及依赖不变，失败批次不归档旧覆盖率，零测试/跳过不能算完整验收。示例见 [第二步身份验证](可信身份入口验证.md)。

**浏览器：** 先启动两版后端及各自 review 演示库；首次安装 `npm --prefix 测试/前端 ci`。本地默认通过 Vite 代理访问 18181/18182。设置 RBAC_BROWSER_CHANNEL=msedge 使用 Edge；需要原表全量核对时设置 RBAC_EXCEL_REVIEW_DIR。

```powershell
npm --prefix 测试/前端 test
```

部署站点改用 RBAC_DEPLOY_BASE_URL 指定根地址，执行 `npm --prefix 测试/前端 run test:remote`，不启动 Vite；它只复用 3 项入口/隔离测试，不等于完整 23 项。HTTP/浏览器部署检查会修改合成演示数据，见 [部署验证](部署验证记录.md)。
