# C3 开发方向细节 · RBAC3

状态：阶段方案，待 C2 验收及 C3 课程细则确认。参见 [阶段需求与验收](./阶段需求与验收.md) 和 [C2 开发方向](<../c2-rbac1-面向功能+面向对象（后端+部分前端）/开发方向细节.md>)。

## 复用 C2

两条后端各沿用对应 C2 版本、契约与迁移，分别使用 `ooad_rbac3_func`、`ooad_rbac3_oo`。继续复用登录、默认工作区、系统下拉及 C2 已实现的申请 CRUD、查看权和组织策略规则；C2 最终基线待其 [六项收尾](<../c2-rbac1-面向功能+面向对象（后端+部分前端）/收尾清单.md>) 及验收完成后确定。若启用会话角色激活，在当前业务系统内另设角色选择。

## 新功能及依赖

| 模块 | 扩展 |
| --- | --- |
| 数据与初始化 | 追加约束及角色关系，准备统一继承与互斥样本 |
| 授权配置 | 校验分配、约束修改及继承变更是否造成冲突 |
| 实时授权 | 保留继承与组织规则。若启用动态约束，按最新分配、继承和规则校验会话激活角色 |
| 契约与验收 | 新增约束维护及冲突响应。需要动态约束时增加会话激活接口。两版回归 C1、C2 并验证继承与约束联动 |

建议以角色集合和约束规则为输入，将互斥判定写成返回冲突结果的纯函数。Service 负责事务、会话和数据读写。功能版按步骤调用，对象版在应用 Service 与领域对象之间分配职责。

## 交付与待确认

交付两套可运行的后端及对应完整前端，提交约束、继承和函数式设计说明以及共同验收记录。验证约束冲突时数据不发生部分更新。

C3 实施前确认静态／动态约束范围、约束检查直接或继承角色的口径、规则变更对已有分配和会话的处理、函数式展示范围以及第三次检查的细则。
