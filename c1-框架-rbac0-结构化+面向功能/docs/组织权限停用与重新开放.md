# C1 组织权限停用与重新开放

C1 后端已实现业务系统动作的组织级停用、重新开放和范围重授。前端连接及课程环境验收待完成。接口见 [组织权限接口设计](../api/组织权限接口设计.md)，基础数据关系见 [数据库设计](./数据库设计.adoc)。

## 操作与生效范围

- 超级管理员按「组织＋业务系统＋权限码」执行停用与重新开放。后端解析该系统下唯一的权限 ID。公司级范围覆盖公司及其下属部门，部门级范围覆盖本部门。系统准入、普通分配的管理员权限和管理范围依原规则检查。
- 系统归属组织及其上级公司适用停用规则。非超级管理员还检查当前员工归属的部门或公司及上级公司。适用范围内任一停用即拒绝，其他系统的同名权限各自计算。停用与重新开放只作用于相应动作，员工使用原会话，仍可进入其有权访问的系统、查看申请列表。
- 停用提交后，下一次审批拒绝所有角色路径，也拒绝超级管理员。重新开放提交后，超级管理员恢复默认操作权，仍须通过系统、其他适用组织、资源及业务状态检查。其他账号即使已有对应角色授权，也需对相应范围和角色显式重授。
- 重授指定一个已具备该动作的角色，只恢复该范围内经此角色取得的操作权。共享角色在其他组织继续按各自规则授权。后续员工加入已重授的角色，按当前关系取得权限。员工离职、管理员离职或失去管理资格，按原有员工状态和分配规则处理。

## 数据与事务

| 组织和动作状态 | 实时授权结果 |
| --- | --- |
| 无配置或 `OPEN` | 按现有系统准入、超级管理员默认能力或角色路径检查 |
| `DISABLED` | 拒绝该动作 |
| `REOPENED` | 超级管理员按默认能力检查；其他账号须有符合范围重授要求的角色路径 |

1. 扩展现有 `organization_permission` 状态约束。另存组织、角色和权限的重授关系，三列组成唯一键；通过外键绑定组织策略记录和 `role_permission`。角色权限撤销时一并移除其重授记录，避免同一角色权限以后重建时继承旧重授。
2. 停用时在同一事务写入 `DISABLED`，并清除该动作在停用范围内的已有重授记录。公司停用同时清除下属部门的重授记录，部门停用只清除本部门对应记录。原始员工–角色及角色–权限分配保留，以便其他组织或动作继续使用。重新开放只把当前范围的 `DISABLED` 改为 `REOPENED`，不生成任何重授。重复停用、重新开放或提交同一重授按幂等处理。
3. 通过独立的范围重授用例写入关系，首版由超级管理员操作。要求目标组织处于 `REOPENED`，角色与权限关系存在且可用于目标范围。目标组织及其上级、系统归属组织及其上级存在停用时拒绝重授；个别下属部门的停用继续在该部门判权时拦截。对同一动作的停用、开放和重授事务使用统一锁顺序及同一权限记录串行化；涉及移除角色权限的写入遵守同一顺序。接口只在提交后返回成功。
4. 普通判权对每条候选角色路径检查适用的 `REOPENED` 范围。同一条角色路径须满足每个适用范围的重授要求。公司与部门叠加时，部门重授不会跳过仍有效的公司规则。首批普通授撤权接口只管理原有两类关系，不能替代范围重授。
5. MySQL 保持唯一约束和引用一致性，迁移只追加。现有 `OPEN` 和 `DISABLED` 记录保持原语义。授权按请求读取数据库，Redis 会话只保留身份。C2、C3 沿用组织策略；C2 将候选路径扩展为包含继承的路径，C3 在有效路径基础上应用约束。各阶段用相同的范围停用与恢复用例对照。

## 开发和验收

普通授撤权、实时审批和组织策略使用同一套在线会话进行 HTTP 回归。Flyway V5 扩展组织权限状态并新增范围重授关系。路径、参数与响应见 [OpenAPI](../api/openapi.yaml)。

| 场景 | 预期 |
| --- | --- |
| 工程部和财务部共用角色，停用工程部的某个公司系统动作 | 工程部成员用同一会话审批被拒绝，包括有多条授权路径的员工；财务部和同名的其他系统动作照常 |
| 工程部自有系统的动作先停用，再重新开放 | 停用期间超级管理员和工程部员工均被拒绝。重新开放后超级管理员恢复默认能力，工程部员工仍被拒绝；明确重授目标角色后，经该角色的员工恢复 |
| 停用公司动作后恢复，并叠加部门停用 | 本公司直属员工及全部下属部门先受停用限制；公司恢复后，其下仍处于停用的部门继续被拒绝 |
| 公司与部门对同一动作均曾停用且都已重开 | 仅重授公司或部门仍不足；对两个范围重授同一条有效角色路径后，对应部门成员恢复 |
| 重复提交和先后交错的停用、恢复、重授 | 状态及重授关系一致；再次停用会清理前次重授；角色权限删除后重建需要重新进行范围重授 |
| 普通员工或公司、部门管理员尝试变更组织策略 | 返回 403，策略及已有分配保持原状态 |

本地 HTTP 回归覆盖两级叠加、共享角色隔离、重授幂等、再次停用和管理员失去资格后保留原分配。并发用例分别提交停用与重授、重新开放与重授，检查最终策略、重授记录和审批结果。管理页面已通过停用、重新开放和重授的浏览器回归，见 [本地验收记录](./本地验收记录.md)。
