== 范围与设计方法

C1 以数据和处理过程划分功能，按输入、处理、输出及失败路径组织用例。Controller 负责参数和响应，Service 负责规则及事务，JPA Repository 读写 MySQL。Spring Security 与 Redis 会话提供每次请求的可信员工身份。管理端及业务端同源运行，共用登录与系统切换。

== 数据初始化

. Flyway 迁移后，导入器读取员工、部门和功能权限清单。权限清单的系统、模块合并单元格展开，空动作保留为空。
. 员工来源的分公司和部门名称原样保存。正式授权归属采用公司及部门 ID。无法唯一匹配时只保留展示资料，员工暂不可登录或用于分配。
. 部门目录以原表覆盖为准。原表中归类为公司的行保留原上级列，管理员可见性仍按正式组织 ID。
. 重复导入按来源键核对内容，发现冲突回滚本批次。演示账号与模拟审批独立初始化。

逻辑表、主外键和迁移顺序见 link:数据库设计.adoc[数据库设计]。

== 权限分配

image::03-权限分配.svg[权限分配流程]

员工—角色与角色—权限均使用 PUT 创建单条明确关系。管理员写入范围取决于员工归属、角色归属及目标权限可用性。事务内先锁角色，再锁关联员工或权限。重复 PUT 返回 204。非法请求、失败的范围校验和被停用的目标会在提交前结束。

== 权限撤销与组织策略

image::04-权限撤销.svg[权限撤销流程]

DELETE 定位并删除单条关系，重复删除已不存在的关系返回 204。角色权限解除时，对应的组织重授由数据库级联清除。撤销一条路径后，有效权限仍取决于其余路径。管理员离职保留历史分配。

组织停用优先于角色路径，适用范围内也约束超级管理员。重新开放恢复超级管理员默认授权；普通员工需要在同一条有效角色路径上满足适用组织的重授条件。组织策略页面回读所选组织的本级策略。详细规则见 link:组织权限停用与重新开放.md[组织权限停用与重新开放]。

== 实时鉴权与业务结果

image::05-实时鉴权.svg[实时鉴权和业务执行流程]

审批使用申请 ID，从数据库定位系统及 `request:approve` 权限。后端读取当前员工及实时权限关系。请求通过鉴权后，以条件更新保证只有待审批申请能完成操作。

[cols="1,2,2",options="header"]
|===
|状态 |含义 |页面处理
|200 |鉴权通过，审批提交成功 |分别展示鉴权通过与执行成功
|401／403 |会话失效、CSRF、系统准入或权限拒绝 |提示登录或拒绝原因
|409 |已通过鉴权，申请状态已变化 |展示鉴权通过与执行失败，刷新申请列表
|503 |Redis 会话或 MySQL 授权数据不可用 |展示依赖故障，联调用例复验申请状态
|===
