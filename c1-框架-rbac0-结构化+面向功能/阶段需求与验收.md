C1（RBAC0）已完成本地验收并作为后续阶段基线。参见 [本地验收记录](./docs/本地验收记录.md) 和 [开发方向细节](./开发方向细节.md)。

## 一、输入、范围和设计

输入包括 [课程日期图](../项目整体方向规划和技术细节/老师的交付要求/检查日期和内容.png)、[助教与教师细则](../项目整体方向规划和技术细节/老师的交付要求/检查内容.txt)、[开发规划](../项目整体方向规划和技术细节/RBAC_Development_Plan.md)、[技术规范](../项目整体方向规划和技术细节/RBAC_Technical_Conventions.md) 及三份工作簿。检查窗口为 10 月 27–29 日，20 分。补检安排待确认。

- **管理前端**：按 Excel 对照展示员工、部门和软件功能权限清单。在管理员可管理的范围内，对员工、角色、权限及两类分配关系提供增删改查。关系调整以替换分配表达。
- **业务模拟前端**：独立入口，使用当前登录员工执行受保护操作。客户端提交目标操作及业务参数，服务端由会话解析员工并实时查权。页面分别显示鉴权通过／拒绝和执行成功／失败／未执行。操作建议选审批申请，具体规则在业务模拟模块确认。
- **结构化后端**：按员工、角色、权限、两类分配、登录会话、授权和模拟执行组织功能，使用模块结构图和关键流程图说明调用、输入输出及异常路径。统一授权守卫供管理和模拟操作使用。员工、角色、权限、员工—角色、角色—权限构成 RBAC0 核心，登录账号按项目约定关联员工。角色继承列入 C2，约束列入 C3。
- **数据库设计**：陈氏 ER 图表示实体、属性、关系和两组多对多基数。逻辑表另列主键、外键、唯一约束与关联表映射。MySQL、Flyway、JPA 按总览约定执行。

### 已确认的系统入口与账号能力

权限管理系统和业务模拟系统为两个独立前端，同源部署并共用登录入口和会话。管理员默认进管理平台，员工依次选择本部门默认系统、所属公司默认系统、无可用系统状态。页面顶部下拉框仅列出后端判定可进入的工作区。切换系统保持当前登录身份，后端按真实分配检查每次操作。授撤权演示使用独立管理员和员工会话。

| 账号 | 权限管理系统 | 业务模拟系统 |
| --- | --- | --- |
| 超级管理员 | 管理所有组织，维护全局管理角色、跨组织授权和共享定义 | 可进入任意业务系统，默认具备所有仍开放的业务操作权限，仍需满足业务状态等执行条件 |
| 公司管理员 | 管理本公司及下属部门；可维护本范围的员工、角色、权限及分配关系 | 可进入本公司及下属部门的系统，按实际业务权限操作 |
| 部门管理员 | 只管理本部门；可维护本范围的员工、角色、权限及分配关系 | 可进入本部门及所属公司的系统，按实际业务权限操作 |
| 普通员工 | 无管理端入口及管理 API 权限 | 可进入本部门及所属公司的系统，按实际业务权限操作 |

公司和部门管理员可使用上级开放的权限，修改、删除共享定义仍由超级管理员负责。分配时同时校验目标员工、角色和权限范围，阻止通过修改或分配角色扩大自身管理权限。列表及分页总数按管理员可见范围计算。

每名已匹配的员工归属一家分公司，允许直属公司，或归属该公司下的一个部门。管理范围独立配置。业务权限按系统计算，同一权限码可在不同系统分别授予。

管理员撤权或离职后，已完成的分配继续有效。组织取消某业务系统的某项权限时，该组织范围内的员工授权从变更提交后的下一次请求起统一失效。

演示建议使用 `super-admin`、`company-a-admin`、`engineering-admin`、`engineering-employee`，隔离的本地或课堂演示环境统一密码 `1234`，从演示环境配置初始化，MySQL 只保存密码哈希。验收说明为每个账号记录组织、可进入系统和预期操作。

## 二、Excel 到管理端与数据字段

下表是字段覆盖清单。数据字段名称为设计建议，原表定位和列名已核实。需求材料仅记录表结构和聚合统计。

### 员工信息

`市政公司员工信息表.xlsx` 的唯一工作表为 `员工信息`。表头 A1:F1，数据行 2–10001。六列均为文本，10,000 条用户名在当前表内唯一。三份工作簿的位置与获取方式见 [Excel 说明](../excel/README.md)。

| Excel 列 | 管理端展示 | 建议数据字段 |
| --- | --- | --- |
| A 姓名 | 员工列表 · 姓名 | `employee.name` |
| B 用户名 | 员工列表 · 用户名 | `employee.username`，员工来源标识 |
| C 分公司 | 员工列表 · 分公司 | `employee.branch_name` |
| D 部门 | 员工列表 · 部门 | `employee.department_name` |
| E 岗位 | 员工列表 · 岗位 | `employee.job_title` |
| F 电话号码 | 员工资料 · 电话号码，默认遮盖部分数字 | `employee.phone`，字符串 |

员工表没有角色列。岗位和登录账号分别建模，员工角色由明确分配产生。演示登录名是否复用员工用户名在登录模块确认。

### 软件功能权限清单

`市政公司应用软件功能权限清单(1).xlsx` 的唯一工作表为 `市政公司应用软件功能权限清单`。A1:I1 合并为标题，表头 A2:I2，数据行 3–361，共 359 条。A、B 按各自真实合并区域读取锚点后，软件系统＋功能模块＋功能点在当前样本中唯一。

| Excel 列 | 管理端展示 | 建议数据字段 |
| --- | --- | --- |
| A 软件系统 | 功能权限清单 · 软件系统 | `catalog_entry.system_name` |
| B 功能模块 | 功能权限清单 · 功能模块 | `catalog_entry.module_name` |
| C 功能点 | 功能权限清单 · 功能点 | `catalog_entry.feature_name` |
| D 功能说明 | 功能权限清单 · 功能说明 | `catalog_entry.description` |
| E 系统管理员 | 功能权限清单 · 系统管理员 | `catalog_entry.administrator_cell` |
| F 公司领导 | 功能权限清单 · 公司领导 | `catalog_entry.executive_cell` |
| G 部门经理 | 功能权限清单 · 部门经理 | `catalog_entry.department_manager_cell` |
| H 项目经理 | 功能权限清单 · 项目经理 | `catalog_entry.project_manager_cell` |
| I 普通员工 | 功能权限清单 · 普通员工 | `catalog_entry.employee_cell`，可空 |

E–I 是原表角色视角的动作文本，含“全部”“无”、斜杠分隔动作、“本人”限定、`view` 混用及一处空单元格。原表动作按原义对照展示，实际授权使用显式配置的权限码及角色—权限关系。实时分配结果由角色权限管理页展示。

### 部门信息

`市政公司部门信息表.xlsx` 的唯一工作表为 `部门信息`。表头 A1:C1，数据行 2–112，共 111 条，110 条有上级且均能在部门表内找到上级名称。2026-11-13 已确认纳入 C1 管理端展示和验收。

| Excel 列 | 管理端展示 | 建议数据字段 |
| --- | --- | --- |
| A 部门名称 | 部门目录 · 部门名称 | `department.name` |
| B 部门经理 | 部门目录 · 部门经理 | `department.manager_name` |
| C 上级部门 | 部门目录 · 上级部门 | `department.parent_id`，由上级名称解析，根节点可空 |

员工表“部门”与部门表“部门名称”直接匹配仅覆盖 1,000 条员工记录，试用“分公司-部门”匹配覆盖 9,756 条。部门表有 46 条经理姓名对应多名员工。建议用独立只读部门目录展示原表三列，经理显示源表姓名。授权依据显式的公司和部门 ID，先为演示账号、角色和业务系统配置归属。无法确认组织归属的原表员工可导入并保留源字段，由超级管理员核对。待匹配期间不得用于登录或授权。

## 四、验收场景

| 编号 | 场景与预期 |
| --- | --- |
| C1-01 | 课程现场按三份 Excel 逐列比对管理端，公开演示与自动化测试使用合成数据。部门目录展示部门名称、部门经理和上级部门，根部门的上级为空。分页读取员工和权限清单，正确展开权限清单合并列并保留空动作，电话默认遮盖部分数字 |
| C1-02 | 管理员完成必要维护和两类关系的分配与撤销。重复分配、缺失资源及越权操作按契约返回且无非预期写入 |
| C1-03 | 正确凭据登录建立 Redis 会话，错误凭据被拒绝。退出或会话过期后，请求受保护操作得到 401 |
| C1-04 | 有目标权限时鉴权通过，再执行模拟操作。覆盖业务执行成功与业务执行失败两条路径，两类结果分别显示 |
| C1-05 | 无目标权限时得到 403，业务未执行。客户端提交其他员工或角色信息无法提升权限。鉴权基础设施故障时返回约定错误，业务未执行 |
| C1-06 | 保持同一员工会话，撤销其角色或角色权限使唯一授权路径消失，下一次请求被拒绝。仍有授权路径时继续允许 |
| C1-07 | 在服务器演示后端、两端原型和接口，对照 Gitee 代码、AsciiDoc 文档与 JaCoCo 报告复查 |
| C1-08 | A 公司管理员能查看和维护本公司下属部门数据，列表及总数排除 B 公司。A 公司工程部管理员调用同公司其他部门的管理接口被拒绝。普通员工直接调用管理 API 被拒绝 |
| C1-09 | 部门管理员可分配本部门角色和上级开放的业务权限。尝试分配公司管理员角色、修改全局共享定义或使用未开放权限时被拒绝，关系保持原样 |
| C1-10 | 工程部员工可进入本公司系统和工程部系统，访问同公司其他部门专属系统被拒绝。在可进入系统中缺少审批权限时，审批也被拒绝 |
| C1-11 | 超级管理员可进入另一公司的业务系统并审批一条待处理申请，无需配置审批角色。若申请已审批，仍返回业务状态冲突 |
| C1-12 | 员工可进入工程部系统及公司系统，只获得工程部系统的审批权限时，审批仅在工程部系统通过 |
| C1-13 | 管理员被撤权或离职后，其已完成的分配继续生效。组织取消某系统的审批权限后，目标范围内通过多条角色路径获得审批权限的员工均在下一次请求被拒绝，超级管理员在同一取消范围内也无法执行该动作。其他组织和系统的授权仍按各自配置执行 |

## 五、运行依赖与交付边界
