# C1 开发方向细节

参见 [项目需求总览](../项目需求总览.md)、[C1 阶段需求与验收](./阶段需求与验收.md) 和 [C1 后端开发规划](./后端开发规划.md)。本文件记录各开发批次的方案和状态。下文的模块 2 是接口闭环交付批次，涉及后端规划中的登录与会话、授权配置、实时授权、业务模拟和契约验收。

## 模块 1 · RBAC0 数据模型与可复现初始化

**状态：已完成本地验收。** 陈氏图已归档，Flyway V1–V5、JPA、三表导入和演示初始化均已在隔离 MySQL 环境通过验证。三份原表两次导入均为员工 10,000 条、组织 111 条、权限清单 359 条，其中 54 名员工待匹配。参见 [本地验收记录](./docs/本地验收记录.md)、[数据库设计](./docs/数据库设计.adoc) 和 [StarUML 图源](./docs/design/RBAC0-陈氏ER图.mdj)。

管理端已提供独立的只读部门目录，展示部门名称、部门经理和原表上级部门。

**数据库连接。** 本地使用 Navicat 的 `ooad_rbac` 连接访问 MySQL。C1 使用 `ooad_rbac0`，C2 使用 `ooad_rbac1_func` 和 `ooad_rbac1_oo`，C3 使用 `ooad_rbac3_func` 和 `ooad_rbac3_oo`。各应用配置指向自己的库。C2 两版沿用 C1 基线迁移并追加各自的迁移，C3 分别沿用对应的 C2 迁移。两种实现使用同一套验收数据，分别初始化。表结构及迁移历史由 Flyway 管理，Navicat 用于核对。

### 选择理由与输入

员工、角色、权限以及两类分配关系同时支撑管理维护、登录身份关联和实时授权。先确定来源数据、逻辑表与约束，可以在 API 和页面使用这些字段前发现匹配与语义问题，也能尽早形成 C1 验收所需的陈氏 ER 图和数据库设计。

输入为 [课程检查细则](../项目整体方向规划和技术细节/老师的交付要求/检查内容.txt)、[技术规范](../项目整体方向规划和技术细节/RBAC_Technical_Conventions.md)、[代码规范 ZIP](../项目整体方向规划和技术细节/老师提供的skill/projectmgt-code-conventions.zip)、三份 Excel 及已确认的展示与导入口径。C1 阶段文档包含原表位置、字段映射和聚合数据核对结果。

### 工作范围

- 确认员工、角色、权限及两类分配关系的概念设计和逻辑设计。采用整数主键，两类关系由外键与组合唯一约束兜底。预留员工与登录账号的关联设计，账号表及认证流程在登录模块落实。
- 在概念和逻辑设计中表达公司、部门、员工、管理员范围、角色与权限定义的归属、上级开放的权限和业务系统归属。优先用明确的公司和部门 ID 初始化合成演示数据。原表名称保留作展示，有歧义的原表记录先保留待匹配。业务系统入口、跨范围校验和超级管理员授权随对应模块实现。
- 确定导入文件、自然键、文本与空值处理、重复导入行为、错误报告和演示数据。Excel 对照清单单独建模，原表动作列按原义显示。授权演示用可复现的合成员工、角色和权限分配，后续通过管理端配置和更新授权关系。
- 模块交付陈氏 ER 图、逻辑表、结构化详细设计中的初始化流程、Flyway 和 JPA 持久化、初始化与测试说明。管理端使用本模块字段，后续在认证保护下实现列表与维护接口。登录、会话、前端联调、业务模拟、授权 Service 及远端接口同步分别随对应模块确认。

### 设计与实现步骤

1. 锁定 Java 21、Spring Boot、Maven 和 MySQL 的构建与运行配置。C1 最终构建已验证 [CloneFactory 注解处理器](./backend/tools/clonefactory/README.md) 的生成链路。运行和工具配置见 [部署运行说明](./部署运行说明/README.md)。
2. 先完成陈氏 ER 图、逻辑表和字段映射。定义导入键、允许的空值、字符处理与错误报告。建议员工源键用用户名，权限清单用系统、模块、功能点组合，运行时权限用独立权限码。可重复导入按键和内容核对，同内容重复执行无新增，冲突明确报告，修改已有员工或授权走后续维护功能。
3. 以合成样本编写迁移、解析、重复输入、关系约束和事务测试，见证目标行为缺失导致的 RED。真实 MySQL 用于验证迁移和数据约束。
4. 实现初始迁移、JPA Repository 及按已确认范围启用的初始化流程。先验证输入再按业务事务写入，遇到错误回滚。唯一约束在触发写入边界转换为稳定错误，业务数据访问按项目技术规范执行。
5. 运行测试并回归。用字段核对表检查记录数和预期值，检查日志与测试报告只含定位所需的表、行、列和错误类别。更新启动与初始化说明，向下一模块提供数据字典、演示数据和待接入接口的输入清单。

### 已确认的数据处理口径

- **权限清单。** 页面保留原表的角色列和动作文本。实际授权由管理端分配或演示初始化显式配置，清单导入只更新展示数据。
- **数据与电话。** 原表验收使用老师提供的三份工作簿。公开演示与自动化测试使用合成数据，员工页面默认遮盖部分电话数字。
- **员工和管理员归属。** 员工归属一家分公司，可直属公司或归属该公司下的一个部门。管理员的管理范围单独配置。无法匹配组织的 Excel 员工保留原表字段并标记待匹配，确认前不能登录或参与授权。
- **业务权限按系统区分。** 同一个权限码可以出现在不同业务系统。给员工授予工程部系统的审批权限，只在该系统生效。
- **分配与组织撤权。** 分配关系由组织持有，管理员是执行分配的操作者。其失去分配资格或离职时，已提交的分配继续有效。若组织取消某业务系统的某项权限，该范围内所有员工从下一次请求起失去该权限，其他系统和组织的授权继续按原配置计算。首模块表达相应的数据关系，撤权操作及行为验收在授权模块实现。

课程环境的复验状态统一见 [C1 外部复验](./阶段需求与验收.md#外部复验)。

## 模块 2 · 登录、Redis 会话与实时审批授权

**状态：接口闭环已实现并通过本地端到端验收。** 登录、Redis 会话、工作区导航、模拟申请审批及两类分配关系的授撤权已实现。接口见 [OpenAPI](./api/openapi.yaml)，结果见 [本地验收记录](./docs/本地验收记录.md)。

### 实现与交付

- 追加账号和最小审批记录的 Flyway 迁移。账号关联员工，MySQL 保存密码哈希。复用已初始化的演示员工，仅在显式启用的演示环境配置测试凭据。组织待匹配员工无法登录。
- 提供登录、当前身份、退出、CSRF 令牌及工作区导航。Spring Security 处理认证和请求拦截，Spring Session 将会话保存在 Redis。两个独立前端同源部署并共享登录。管理员默认进入管理平台，员工优先进入部门默认系统，其次是公司默认系统，两者都不可用则显示空状态。下拉框展示当前身份可进入的系统，切换只改变路由。演示管理员与员工时使用独立会话。
- 实现业务系统列表和 `POST /api/requests/{requestId}/approve`。审批 Service 从申请记录确定所属系统，统一授权 Service 据此检查系统准入、组织停用和当前权限，再执行审批。普通员工从直接角色实时获得权限；超级管理员默认可执行仍开放的操作。
- 两类分配关系均支持授予与撤销。Spring Security 检查请求入口权限，Service 校验组织与可授予范围。示例由超级管理员修改分配，普通员工保持登录，分别验证授予与撤销生效。员工、角色和权限的维护及页面已在模块 3、4 交付。
- 更新本地 OpenAPI、启动与演示说明和验收记录。用本地请求验证 Cookie、CSRF 和状态码。

### 验收用例

| 编号 | 场景与预期 |
| --- | --- |
| C1-M2-01 | 正确凭据登录并取得当前身份。错误凭据、待匹配员工无法登录。退出或会话过期后，受保护请求无法继续执行 |
| C1-M2-02 | 未提供合法 CSRF 令牌的写请求被拒绝。正常浏览器会话可执行允许的操作 |
| C1-M2-03 | 工程部员工只能进入本公司与本部门系统。在两个可进入的系统中取得同名权限之一时，只能在获权的系统执行审批 |
| C1-M2-04 | 对不同的待审批申请，同一员工会话依次验证缺权 403、授予提交后 200、撤销提交后 403。分别覆盖员工角色和角色权限的撤销 |
| C1-M2-05 | 普通员工无法修改分配，管理员越权分配被拒绝。组织停用阻止范围内的审批；超级管理员可跨系统执行仍开放的操作 |
| C1-M2-06 | 已审批申请返回业务状态冲突，拒绝与错误路径均保持申请原状态 |
| C1-M2-07 | 管理员默认进管理平台。员工依次按部门、公司默认系统和空状态选择入口。下拉按当前可进入的范围显示，切换系统保持同一登录身份 |

### 已确定的接口约定

会话默认空闲超时 30 分钟，Cookie 名为 `SESSION`，写请求使用 `X-CSRF-TOKEN`。登录和当前身份接口共用工作区响应。登录成功后轮换会话 ID，后续写请求重新领取 CSRF 令牌。组织停用、重新开放和范围重授已随模块 3 交付。参见 [组织权限停用与重新开放](./docs/组织权限停用与重新开放.md)。

申请列表按系统分区并按 ID 升序分页。审批使用申请所属系统查询动作；系统归属组织及上级公司中任一停用均阻断该动作，非超级管理员同时检查其所属部门及公司。审批使用仅更新 `PENDING` 记录的条件写入，并发操作只有一个请求成功。
