# 业务模拟

状态：系统目录、申请分页、审批后端已实现。参见 [C1 后端开发规划](../../../../../后端开发规划.md)。

## 应有功能

负责可进入系统所需的业务目录、预置申请、申请列表和审批。

## 实现方式

业务系统由初始化提供，V4 迁移新增申请表。列表按系统编码查询，分页按申请 ID 升序。审批从申请记录确定系统，先判权，再通过条件更新提交待审批状态。已审批或并发请求先提交时返回状态冲突。四个演示系统分别预置六条申请，重跑初始化保留既有申请及状态。

## 代码入口

[BusinessRequestController](BusinessRequestController.java) 接收业务请求，[BusinessRequestService](BusinessRequestService.java) 调用实时授权并更新申请，[SimulatedRequestRepository](SimulatedRequestRepository.java) 提供带状态条件的更新。

## 与其他模块的关键联系

给登录与实时授权提供系统及组织归属，调用实时授权检查准入和审批。C2、C3 沿用同一审批入口和响应。

## 验收

HTTP 用例覆盖分页、系统准入、同码权限隔离、正常审批、拒绝不写入和重复审批冲突。并发提交同一申请时，一个响应为 200，另一个为 409。MySQL 和 Redis 分别断开时审批返回约定的 503，申请仍保持待审批。浏览器已通过同会话授撤权验收，操作见 [前端说明](../../../../../frontend/README.md)。
