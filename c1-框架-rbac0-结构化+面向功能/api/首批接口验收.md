# C1 首批接口验收

本文件记录核心接口的验收场景。接口以 [仓库 OpenAPI](./openapi.yaml) 为准，真实 MySQL 与 Redis 的回归结果见 [本地验收记录](../docs/本地验收记录.md)。使用 Apifox 时按 [部署运行说明](../部署运行说明/README.md#4-配置-apifox-并请求真实后端) 设置前置 URL、会话和契约。

## 会话与导航

- 使用会话 Cookie `SESSION`，默认空闲超时 30 分钟，允许环境配置。两端同源，Cookie 路径为 `/`，使用 `HttpOnly`、`SameSite=Lax`，HTTPS 部署加 `Secure`。
- `GET /api/auth/csrf` 建立或复用会话，客户端保留 Cookie，并在登录、退出、PUT、DELETE 及审批等写请求提交 `X-CSRF-TOKEN`。登录成功后用轮换后的 Cookie 获取新令牌。退出后丢弃原令牌，下一次登录前重新获取。
- 登录和 `GET /api/auth/me` 统一返回 `employee`、`workspaces`、`defaultWorkspaceKey`。合法默认键必须来自可进入列表。管理员默认 `admin`。普通员工依次选本部门可进入的默认系统、所属公司可进入的默认系统，缺少可用默认项返回 `null`。若列表仍有系统，页面允许手动选择。每个组织至多配置一个默认系统。默认项用于导航，实际准入由服务端另行核验。
- 系统切换使用工作区的同源路径，如 `/business/demo-engineering-app/`，刷新页面按当前路径重新获取数据。切换保持同一登录会话，权限按请求重新计算。

## 验收数据

准备超级管理员、公司管理员、工程部管理员、工程部员工与待匹配员工。首次登录与验收由合成账号完成，其中工程部员工应能进入甲公司的工程部系统和公司系统。准备多个独立待审批申请，并记录实际生成的员工、角色、权限及申请 ID。

超级管理员与员工使用两个独立的 Cookie 容器。Apifox 调试时确保两个请求序列使用各自会话的 Cookie 和令牌。开始实时授撤权用例前，只保留一条可控的工程部审批授权路径，或先将它撤销以构造缺权状态。

## 用例与预期

| 编号 | 操作 | 预期 |
| --- | --- | --- |
| C1-M2-01 | 获取 CSRF，正确凭据登录；分别测试错误密码、待匹配员工和停用员工；再测试退出、空闲过期、登录后账号停用 | 登录成功返回 200 并轮换 Cookie；不可登录返回 401 `INVALID_CREDENTIALS`；会话失效后 `/api/auth/me` 返回 401 `AUTHENTICATION_REQUIRED`，写请求若先命中 CSRF 校验则返回 403 `CSRF_INVALID` |
| C1-M2-02 | 使用缺失、其他会话或轮换前的令牌请求写接口 | 403 `CSRF_INVALID`，无业务写入；使用当前会话正确令牌时进入后续检查 |
| C1-M2-03 | 工程部员工查询可进入系统及其申请列表。用该员工审批公司系统申请和工程部系统申请，分别尝试查询同公司其他部门专属系统 | 系统列表含本部门与公司系统。仅授予工程部审批权限时，审批公司申请返回 403 `PERMISSION_DENIED`，审批工程部申请返回 200。访问其他部门专属系统返回 403 `SYSTEM_ACCESS_DENIED` |
| C1-M2-04a | 在同一员工会话中对待审批申请验证缺权。管理员 PUT 员工—角色，员工审批成功。管理员 DELETE 员工—角色，员工再审批另一份待审批申请 | 403 → 204 → 200 → 204 → 403。每次管理响应都在事务提交后返回。最后一份申请状态仍为 `PENDING` |
| C1-M2-04b | 保留员工—角色关系，以 PUT、DELETE 角色—权限复现同一链路。重复 PUT、DELETE。另加一条有效授权路径后只撤掉其中一条 | 幂等请求返回 204。唯一授权路径消失后拒绝。仍有其他有效路径时可审批 |
| C1-M2-05 | 普通员工写入任一分配接口；部门管理员尝试操作其他部门；用验收数据构造组织停用；超级管理员跨组织审批仍开放的申请 | 未授权或跨范围分配返回 403 `PERMISSION_DENIED`，关系不变。组织停用阻断范围内所有路径及超级管理员审批。超级管理员可审批其他系统中仍开放的动作 |
| C1-M2-06 | 对已经审批的申请重复审批；查询不存在的系统；审批不存在的申请；模拟授权数据不可用 | 分别返回 409 `REQUEST_ALREADY_APPROVED`、404 `SYSTEM_NOT_FOUND`、404 `REQUEST_NOT_FOUND`、503 `AUTHORIZATION_UNAVAILABLE`。请求未新增业务写入 |
| C1-M2-07 | 分别登录管理员、拥有部门默认项的员工、仅有公司默认项的员工、没有可用默认项的员工。用同一会话切换已获准进入的系统 | 默认键分别为 `admin`、部门系统键、公司系统键、`null`。会话保持当前员工身份，后端按切换后的目标系统检查操作 |
| C1-05 | 已获审批权限的员工保持登录，在隔离环境分别断开 MySQL 与 Redis 后提交待审批申请 | HTTP 503，错误码分别为 `AUTHORIZATION_UNAVAILABLE` 与 `SESSION_UNAVAILABLE`。依赖恢复并可重新查询后，两条申请仍为 `PENDING`。复验命令见 [C1 README](../README.md) |

补充检查分配接口的两端资源不存在、禁止建立关系和分页参数非法，分别核对 404 `RESOURCE_NOT_FOUND`、409 `ASSIGNMENT_CONFLICT`、400 `VALIDATION_FAILED`。审批成功以 `authorization=GRANTED` 和 `execution=SUCCEEDED` 表示。失败时用错误码区分授权拒绝、前置检查失败及已通过鉴权后的业务冲突。

初始用例通过测试数据验证停用优先。完整组织权限策略使用 [组织权限接口](./组织权限接口设计.md) 触发，验收见 [组织权限停用与重新开放](../docs/组织权限停用与重新开放.md)。
